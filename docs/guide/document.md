## 1. 什么是中医医案管理系统

**中医医案管理系统**是 ClawDao 生态下的一个本地应用，定位为：

- **面向对象**：中医师 / 中医诊所 / 跟诊学员
- **核心功能**：把传统纸质的「跟诊记录表 / 门诊病历」电子化、结构化、可检索

它有 3 个特别的能力：

| 能力 | 说明 |
| --- | --- |
| 🖼 **拍照建案** | 用手机 / 相机拍下纸质病历 → 自动 OCR 识别 → 一键预填表单 |
| 🤖 **AI 录入** | 通过 ClawDao 龙虾岛的"数字员工"，让大模型直接读取图片并写入系统 |
| 📊 **统计 / 字典** | 内置疾病、中药、证型、方剂的本地字典，方便后续做数据统计 |

## 3. 第一步：在 ClawDao 龙虾岛中打开应用

医案系统不是一个独立的桌面 App，它是 **ClawDao 龙虾岛**里的一个"应用"（类似 Docker 容器）。所以，第一步永远是先打开龙虾岛。

### 3.1 找到入口【这个是直接入口，什么时候都能用】

打开 ClawDao 龙虾岛 → 左侧菜单 → **应用**（puzzle 图标）→ 顶部出现 **我的应用** 列表。

![应用列表](screenshots/001.png)

你应该能看到一张卡片写着「中医医案管理系统」：

- 标签：**中医 · 医案 · OCR · 统计**
- 描述：中医医案管理系统（Koa + React + Ant Design + Tailwind + CLI）
- 状态：本地 / v1.0.0

### 3.2 启动应用

点击卡片左下角的 **▶ 运行** 按钮。

- 首次运行会先做依赖安装（Koa 后端 + Vite 前端），需要 30 秒～2 分钟。
- 运行成功后，卡片状态从「已下载」变成 **绿色"运行中 → http://localhost:5174/"**，并出现 **停止 / 主页 / 终端 / 详情** 四个按钮。

![启动后的卡片状态](screenshots/002.png)

> 4 个按钮的作用：
>
> | 按钮 | 干什么 |
> | --- | --- |
> | **停止** | 关闭服务，释放端口 |
> | **主页** | 在龙虾岛内置浏览器里打开 http://localhost:5174/ |
> | **终端** | 打开项目根目录的 shell（看日志、改配置） |
> | **详情** | 看 README、版本号、目录路径 |

### 3.3 故障排除

如果点了"运行"卡片没反应：

1. 去左侧 **老板** 页面，跟"老板"说："把『中医医案管理系统』安装好并启动"。
2. 或者去 **终端**，手动执行 `cd /Users/imfly/Documents/projects/Agents/中医医案管理系统 && pnpm dev`。
3. 端口冲突时改 `vite.config.ts` 的 `server.port`。

## 5. 第三步：拍照建案（推荐上手路径）

> 这是医案系统最有特色的功能：**把纸质病历拍照，让系统自动识别并预填表单**。

### 5.1 找到入口

左侧菜单 → **拍照建案**（相机图标）。

### 5.2 上传照片

页面中央是一个 **虚线框的上传区**：

- **支持格式**：jpg / png / webp
- **大小限制**：单张不超过 **10MB**
- **方式 1**：点击虚线框 → 弹出文件选择器 → 选图片
- **方式 2**：直接把纸质病历的照片 **拖拽** 到虚线框里

> 💡 拍照小技巧：把纸摊平、光线均匀、避免反光；尽量让"跟诊记录表"的整个表格都在画面里，OCR 准确率最高。

### 5.3 自动 OCR 识别

上传后，系统会自动跑一遍 OCR，把图片中的字段提取出来。识别成功后：

- 顶部出现绿色提示：「✅ 识别完成。请务必逐项校对识别结果后再提交，识别有误之处请直接修改。」
- 页面分两栏：
  - **左**：原始图片（病历原件，便于和识别结果对照）
  - **左下**：OCR 识别原文（一段纯文本，方便排查识别错误）
  - **右**：**校对医案信息**（分 6 步的表单，已自动填充识别结果）

### 5.4 6 步校对表单

右上角有 6 个步骤指示器：

```
1 基本信息 → 2 患者信息 → 3 四诊信息 → 4 诊断辨证 → 5 处方信息 → 6 疗效随访
```

前 4 步在识别成功后显示 **绿色 ✓** 表示已完成识别，可以直接修改；第 5 步（处方信息）当前正在校对中，第 6 步（疗效随访）尚未识别。

**第 5 步「处方信息」界面**包含：

- **方剂名称**：例 "柴胡疏肝散加减"
- **剂数**：例 7
- **用法用量**：例 "每日一剂，水煎分早晚温服"
- **医嘱**：例 "忌食生冷辛辣，调畅情志"
- **药物明细表格**：
  - 复选框 / 药名 / 剂量 / 脚注选择 / 删除按钮
  - 可点击「**+ 添加药物**」新增行
  - 可点击「**套用模板**」一键填入常用方剂的药物列表
  - 可点击「**存为模板**」把当前处方保存为模板供后续复用

### 5.5 提交

每一步都有「**上一步 / 下一步**」按钮。第 6 步点「**完成**」即保存一条新医案。

> ⚠️ **当前演示数据是模拟的**：截图里红字标注"没有 OCR 模型，识别数据是模拟数据"。在正式使用前，需要在项目 `server/` 下配置真实 OCR（如 PaddleOCR / 百度 OCR / 通义千问 VL），否则识别结果可能是 mock 数据。

## 7. 第五步：编辑医案（6 步向导）

点详情页右上 **编辑**，或新建医案，会进入 **6 步分步表单向导**：

```
[① 基本信息] ─── [② 患者信息] ─── [③ 四诊信息] ─── [④ 诊断辨证] ─── [⑤ 处方信息] ─── [⑥ 疗效随访]
   ✓ 已完成           ✓ 已完成         ✓ 已完成         ✓ 已完成         ← 当前        →  待完成
```

> 步骤条用 **绿色填充数字 + 灰色数字** 区分当前和未完成。

### 7.1 步骤 ① 基本信息

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| **就诊日期** | ✅ 红星 | 日期选择器，格式 YYYY-MM-DD |
| 医案类型 |  | 下拉：初诊 / 复诊 |
| 接诊医师 |  | 文本，默认填当前登录账号名 |
| 医案来源 |  | 下拉：手工录入 / 图片 OCR / AI 录入 / 其他 |

### 7.2 步骤 ② 患者信息

- 患者姓名（必填）
- 性别（下拉：男 / 女 / 未知）
- 年龄（数字，单位岁）
- 联系电话
- 既往史（多行文本）

### 7.3 步骤 ③ 四诊信息

6 个字段一一对应中医四诊：

- **主诉**（必填，一句话概括）
- **现病史**（必填，多行）
- **望诊**（面色、形态、舌象等）
- **闻诊**（声音、气味）
- **问诊**（寒热、汗、饮食、二便等）
- **切诊**（脉象）

### 7.4 步骤 ④ 诊断辨证

- 中医诊断（病名，可选多个）
- 西医诊断
- 证型
- 治法

> 这 4 项都可点击 **「+」** 按钮调用数据字典做下拉联想。

### 7.5 步骤 ⑤ 处方信息

参考 [§5.4](#54-6-步校对表单) 中关于「处方信息」的描述，此处完全相同。

### 7.6 步骤 ⑥ 疗效随访

- 疗效（下拉：治愈 / 好转 / 未愈 / 未知）
- 按语（医嘱、注意事项、生活调摄）
- 备注

最后一步点 **「完成」**，医案写入数据库，回到列表或工作台。

## 11. 常见问题 FAQ

**Q1：医案系统启动后浏览器是空白页？**
A：先看 ClawDao 应用卡片上的 URL 是否能访问（http://localhost:5174/）。若 404，看下 Koa 后端是否启动（`curl http://localhost:5174/api/health`）。若后端 500，看终端日志。

**Q2：OCR 识别出来全是错的字段？**
A：截图里已经标注了"没有 OCR 模型，识别数据是模拟数据"。需要在 `server/ocr/` 下接入真实 OCR（PaddleOCR-VL 或百度 OCR）。纸质病历模糊 / 反光也会显著降低识别率。

**Q3：能多人同时使用吗？**
A：可以，但默认只跑在 localhost。多人用需要：
1. 改 Koa 的 CORS 配置 + 监听 0.0.0.0
2. 把数据库从 SQLite 迁到 PostgreSQL / MySQL
3. 给每人开账号（系统管理 → 用户管理）

**Q4：能不能只录方剂不录四诊？**
A：可以。四诊里非必填的可以不填，但工作台统计可能不准。

**Q5：删除的医案能找回吗？**
A：详情页有 **「删除」** 和 **「彻底删除」** 两个按钮。前者走软删除，后者走硬删除。硬删除前请确保已下载 JSON 备份（详情页有"导出 JSON"按钮）。

**Q6：数据存在哪里？**
A：默认 SQLite，文件在 `server/data/medical-case.db`。建议每周通过系统管理 → 数据备份导出。
